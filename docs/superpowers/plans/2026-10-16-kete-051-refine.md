# 0.51: refine the bench

Follows 0.49 (one registry, one key table, verbs menu, diff against base) and 0.50 (Review/Ship board, scope,
review unit, ship). Jay, 2026-10-15: "continue through to release 60 as needed to build/refine this".

## Goals
1. **Know which session made which change.** When several sessions share a worktree, the review unit can show
   each one's changes.
2. **Record a worktree's base when it is cut** instead of deriving it, so the review and Ship lanes stay right
   after the base branch moves or the setting changes.
3. **Close the remaining CLI ↔ app gaps** from the 0.49 parity audit.
4. **Look at every new screen** at real sizes and fix what looks wrong.
5. **Faster large pastes on Windows.**

## Deliverables

### `lane/attribution` (daemon, core, both apps)
- At session start and at each turn boundary (finished/needs-feedback), the daemon records the worktree's HEAD
  and a tree snapshot of the dirty files (`git stash create`-style object or `write-tree` on a temp index, no
  working-tree change), stored per session in the db.
- Core function: a session's changes = diff between its start snapshot and its last turn snapshot.
- Review unit gets a session filter: "this session / all sessions in this worktree". Wire: new optional request,
  protocol bump, gated clients.

### `lane/base-record` (daemon)
- Store the base ref and merge-base sha on the worktree row when Kete cuts it; `review_base` prefers it, falls
  back to the derived base for older worktrees. Backfill nothing.

### `lane/parity-leftovers` (both apps, CLI)
- TUI ADO overlay: vote and reply on a PR (the desktop has both).
- Orchestrator start: model and effort in the TUI; project and name in both apps.
- TUI manual "Delete merged & clean worktrees…" like the desktop's.
- Config export/import from Settings in both apps (CLI has `kete config export/import`).
- Rename a profile used by sessions: daemon request that rewrites sessions' stored profile name.
- Old TUI `pane_footer_hint` word lists moved onto the registry.

### `lane/visual-qa` (desktop via the demo bridge in Chrome; TUI via draw tests)
- Every 0.48–0.50 desktop screen at 640, 900 and 1280 widths, light and dark: verb bar, Hotkeys, Accounts,
  scope chip, review split, ship sheet, worktrees view. Fix what's broken; add draw tests for TUI screens at
  80×24 and 120×40.

### `lane/paste-speed` (TUI, Windows)
- Read console input records in bulk during a paste burst (ReadConsoleInputW with a large buffer) instead of one
  crossterm event at a time.
