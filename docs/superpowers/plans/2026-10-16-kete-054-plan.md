# 0.54: reach, look, wake, critters (one release train)

The spec is docs/superpowers/specs/2026-10-16-kete-054-reach-design.md. Jay, 2026-10-16: "ensure we work plan all scopes/engineer decisions, and implement action releases in parallel effectively. And merge/release/test at end."

So everything in the spec (its 0.54–0.57 outline) ships as **one release, 0.54.0**:
- The lanes run in parallel waves.
- All of them merge into `release/0.54`.
- There is one release gate at the end, then the release.

The ledger is in `.superpowers/sdd/2026-10-16-release-054/`, and each lane brief there is `lane-<name>.md`. The shared rules are in `brief.md`.

## Engineering decisions (recorded so lanes don't relitigate them)

1. **One release.** It ships at the end (Jay's test cadence: targeted tests per lane, one full gate per release).
2. **Waves.** At most four lanes compile at once. The machine has 32 GB, often about 9 GB free, and one flaky CPU core: no stress loads, `CARGO_BUILD_JOBS=3`, per-crate tests only.
3. **The foundation lands first** on `release/0.54`:
   - registry kinds (`file`, `folder`, `account` menus)
   - the new verb ids
   - critters settings rows
   - editor prefs
   - protocol slots: 61 wake, 62 limits
   Lanes only append after that.
4. **Menus are HTML (Kete-styled), not native Tauri menus**, because native menus can't be themed or carry icons on Windows.
   - WebView2's default menus are off.
   - Browser accelerator keys are off in release builds. Editing keys stay, and F12 stays in debug builds.
   - Text fields, the terminal and Monaco get Kete's own Copy/Paste menus.
5. **Menu = f(target) in both apps.** The registry's `MENUS` plus local rows for PR, branch, task and critter. The TUI resolves the clicked target via `hit_to_target`, and omits headings, separators and disabled rows.
6. **Editors.**
   - Detection and launch live in `nebula_core::editors`.
   - Kete spawns the exe directly with Kete's environment stripped.
   - Visual Studio appears only where a solution or project exists.
   - Focus works by relaunching. Window titles drive only the "open" dot.
   - "Dock beside Kete" via `SetWindowPos`. No embedding, no `serve-web`.
7. **Whakaoho.**
   - State lives in `config.local.json` `wake` plus `<data>/wake-log.jsonl`, never config.json.
   - The default mode is a hidden interactive session through daemon request 61, because `-p` may bill API credits and not start the window. Print mode is a fallback.
   - Windows Task Scheduler XML runs `kete wake --all`.
   - Off by default, per account.
8. **Limits.**
   - `StopFailure`, the quota auto-resume notifications and the blocking-dialog notifications become row state, as side fields behind protocol 62. There is no new `AgentStatus`.
   - Effort is synced from the statusline and hooks.
   - Windows hooks move to exec form.
   - `background_tasks` replaces the timers.
9. **Critters.**
   - A Rust crate is the single source of the art and data, with a generated TS cast and a drift test.
   - The behaviour is ported to TS for the desktop.
   - The TUI draws with half-blocks.
   - Off by default. Discovered via Settings, the `critters` verb, the Konami code, or five clicks on the kete mark.
   - The collection log stays machine-local.
   - Original art only.
10. **Look.**
    - The JSONC and VS Code theme loader move from nebula-tui to nebula-config, so the desktop shares them.
    - Fonts must be system-installed, because the CSP allows no external fonts. The backend enumerates them.
    - A free-text desktop pref path is added for font families.
11. **Files.** The tree is `git ls-files` plus untracked-not-ignored files, served only under the worktree root. Dragging a row onto a session or terminal inserts its path.
12. **Consolidation** removes duplication, never features. Every move is listed in the CHANGELOG.

The orchestrator merges each lane into `release/0.54` as it reports:
- It re-runs that lane's targeted tests on the merge.
- It resolves the registry, protocol and CHANGELOG-paragraph order.
- It then refreshes waiting lanes with `git merge release/0.54`.

## Release (at the end)

1. Merge `main` (0.53.1) into `release/0.54`.
2. **Full local gate, one crate at a time:**
   - `cargo fmt --check`
   - `cargo clippy --workspace --all-targets -D warnings`
   - `cargo test -p` for each crate in turn: nebula-config, nebula-core, nebula-daemon, nebula-tui, nebula, kete-ado, kete-critters
   - desktop: `npm run check`, `npm test` and clippy
   - desktop e2e once
   - Linux clippy in Docker only if memory allows. Otherwise CI covers it.
3. Version 0.54.0 everywhere the 0.53.1 bump touched. Write the CHANGELOG (both copies) from the lane paragraphs. Add What's new entries in learn.rs.
4. Open a PR from `release/0.54` to `main`. Get CI green on three OSes, merge, then tag `v0.54.0`. `release.yml` builds and publishes the seven assets.
5. Hand back to Jay with:
   - install steps
   - the morning Whakaoho check: `kete wake status`, then `kete wake jayrich --dry-run`, then one real wake. Compare `resets_at` before and after.
   - a smoke list
   - decisions only he can make
